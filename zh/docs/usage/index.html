使用手册

使用手册

下面的步骤在一份干净检出上跑 CPU/TCP 契约。它们不安装软件包，不格式化磁盘，也不打开 DPU。BlueField-3、GDS、DPU 硬件路径，以及真实的 RDMA/NIXL 性能，仍然是「开发中」。

开发中

没有生产部署，也没有 crates.io 发布。Soft-RoCE 只做功能冒烟，不是性能数字。G3.5 未命中或节点丢失是一次干净的未命中：重算，再写回。没有纠删码，热层也没有持久副本。RustFS 是 G4 冷层。

安装启动演示配置配额未命中运维说明

安装

rust-toolchain.toml 选择 Rust stable。声明的 MSRV 是 1.85。没有可安装的包。克隆仓库，然后跑 CPU 契约测试：

git clone https://github.com/rustfs/GPUCache.git
cd GPUCache
cargo test --workspace --all-targets

cargo test --workspace --all-targets 是 V1 A、V1 B 和 V1 C 的一条命令 CPU 复现，也覆盖树里已有的 V2 和 V3 CPU 测试。字节是合成的。它们不是 vLLM KV 张量，这条命令也不是带宽结果。CI 还会跑 cargo fmt --all -- --check 和 cargo clippy --workspace --all-targets -- -D warnings。

启动

除非你明确放开，TCP 服务只听环回。默认绑定是 127.0.0.1:9735。非环回地址需要 --allow-remote。这个标志不关闭认证。进程仍然要求租户凭据指纹：32 字节，十六进制，不能全零。传入哈希，不要传入活的密钥。没有不认证的数据路径。

cargo run -p gpucache-transport --bin gpucache-tcp -- serve --data-dir /tmp/gpucache-dev --tenant tenant-a --trust td-local --fingerprint <64 hex chars of a credential hash>

--data-dir 是普通文件目录（MANIFEST、LRU 和 blocks/*.gblk）。不要把它指到设备节点。进程不格式化 NVMe，不改网卡，也不碰 DPU。没有磁盘上的配置文件。标志就是配置模式。这个例子只是开发用的环回。

演示

每条成功横幅都是正确性检查。它们都不是性能数字。BlueField-3、GDS 和在线 RDMA 保持 NOT_RUN_HARDWARE。

命令成功横幅它是什么
cargo run -p gpucache-transport --bin share-demostatus=REUSE_OK 和 partial_prefix=WHOLE_BLOCK_PREFIX两个本机客户端共用一个文件后端服务。更长的链复用整块更短的 block。更短的 valid_length 不会被切出来。intra_block_slice=DEGRADED_MISS。
cargo run -p gpucache-transport --bin fault-demostatus=FALLBACK_OK、criteria=EXACT_TOKEN_IDS、tolerance=NONE命中、未命中、损坏文件、截止时间、取消和配额拒绝都失败关闭。调用方重算。错误的租户或错误的模型不是命中。不是 vLLM 运行。
cargo run -p gpucache-transport --bin shard-demostatus=SHARD_OK、registration=SIMULATED、rdma=NOT_RUN_HARDWARE一个分片、epoch 隔离、租约到期后的隔离，以及一次 TCP 主机拷贝。不是网卡注册。
cargo run -p gpucache-cold --bin cold-demostatus=COLD_CONTRACT_OK 和 gds=NOT_RUN_HARDWAREG4 的 mock 打包、下沉和按预算截断的回填。没有配置端点时 rustfs_live=NOT_RUN_HARDWARE。
cargo run -p gpucache-dpu --bin dpu-demostatus=DPU_CONTRACT_OK、offload_active=false、hardware=NOT_RUN_HARDWARE、doca=NOT_LINKED进程内的 DPU 契约。它不打开设备。Arm 进程启动不是卸载。
cargo run -p gpucache-bench --bin paired-baselineNOT_RUN_HARDWARE，没有时延数字成对的 GPU 基线没有跑。工具不打印样本数、TTFT 或 tokens/s。
cargo run -p gpucache-bench --bin v3-pairedTCO_UNKNOWN 和 go_gate=NOT_EVALUATED点名 NIC RDMA 与 DPU 的对照，但不测量。TCP 不是那条基线。
cargo test -p gpucache-dpu --all-targets --features dpu-bf3测试通过，打开被拒绝可选特性槽。不链接 DOCA、SPDK 或 NVMe。
cargo test -p gpucache-transport --all-targets --features rdma-nixlNixlTransport::open 拒绝不链接 libnixl。Soft-RoCE 只做功能冒烟，不是性能数字。

kv-block-xfer 从标准输入读一帧 GEXP，导入一个新的 MemoryStore。只有 lookup 和 get 都成功才打印 status=IMPORTED。校验失败以退出码 2 结束。它不连接引擎。

cargo run -p gpucache-storage --bin kv-block-xfer -- import <64 hex chars of a credential hash>

配置

没有配置文件。二进制标志和 ResourceLimits::dev_defaults() 就是模式。

字段默认含义
bind127.0.0.1:9735套接字。非环回需要 allow_remote。测试使用端口 0。
data_dir必填普通文件目录。不是设备节点。
tenant、trust、fingerprint必填一条 V1 策略。指纹是 32 字节，不能全零。
allow_remotefalse不关闭认证。
max_connections16超出的连接被丢弃。
max_frame_bytes库内 1 MiB，二进制 2 MiB正文上限。声明更大的长度会在读取前被拒绝。
pool_buffers16读缓冲池。达到上限时取出失败。
io_timeout5 s每条连接的读写超时。

除非操作者已经授权测试桶，否则不要设置 GPUCACHE_RUSTFS_ENDPOINT、GPUCACHE_RUSTFS_BUCKET、GPUCACHE_RUSTFS_PREFIX、GPUCACHE_RUSTFS_ACCESS_KEY 和 GPUCACHE_RUSTFS_SECRET_KEY。未设置就是 NOT_RUN_HARDWARE。不要编造凭据。本阶段的 https:// 是 NOT_RUN_HARDWARE，因为没有链接 TLS 栈。

配额

ResourceLimits 限制对象大小、在途请求、注册（含已提交和已隔离的缓冲）、每租户在途字节、全局保留字节和每租户保留字节。幂等表有上限，条目会过期。

MemoryStore 在准入失败时直接拒绝，不驱逐。FileStore 在保留字节配额将要失败时，驱逐最旧的、未固定的已提交 block。它不会为了满足一个租户的配额去驱逐另一个租户，也不会驱逐已固定或已隔离的 block。Invalidate 是客户端的显式路径。

分片额度、模拟 slab 上限、冷保留和回填字节预算，都是可重算 KV 的准入天花板。它们不是测过的集群规模。不要把热层当成用户数据的唯一副本来做容量规划。

失败与未命中

GPUCache 是 G3.5 共享热层。RustFS 是 G4 冷层。G3.5 未命中或节点丢失时，结果是一次干净的未命中，然后重算，再写回。没有纠删码，热层也没有持久副本。

  • 命中只属于身份兼容、且校验和仍然相符的 COMMITTED block。
  • ABSENT、RESERVED、WRITING、EVICTING 和 QUARANTINED 不返回载荷。
  • 未命中、超时、校验失败、版本不匹配、存储不可用、超预算回填、被隔离的 epoch、损坏或截断的文件，以及传输错误，都是重算。它们都不是成功的命中。
  • 错误的租户、模型、分词器、适配器或布局不是命中。错误的命中是故障。
  • 同一条哈希链上更短的 valid_length 是不兼容的未命中。服务不会在 block 内部切片。
  • 租约到期不能证明拷贝已经停止。隔离区域会留到排空证明，或一个更新的被隔离 epoch。
  • 重启会重新加载已提交文件，抬高 epoch，并丢掉在途预留。
  • DPU 重启、GPU 复位、网卡闪断、存储丢失、NVMe 超时、控制面丢失，以及 RustFS 变慢或宕机，这些降级决定都是干净的未命中。这张表不是硬件故障注入。没有载荷，没有错误命中，没有永久阻塞。

引擎可以通过同一套批量 API 把重算后的 block 写回。热层不会自己修复丢失的 block。

运维说明

dpu-demo 是诊断草图。它打印是否选了 dpu-bf3，DOCA、SPDK 和 NVMe 没有链接，热层纠删码是关的，以及每个计划中的目标都是 NOT_RUN_HARDWARE。它不打印载荷、指纹或 prompt。因为没有打开设备，所以没有设备健康计数器。

ControlPlane::begin_upgrade 停止新的填充。在途填充仍可以完成。完成前的 rollback 回到服务，不隔离。finish_upgrade 抬高软件代际并隔离，于是旧 epoch 未命中，引擎重算。完成后的 rollback 会再次隔离。代际计数不会减小。这次回滚不包括 BlueField 固件、BFB 或 DOCA 包。除了错误应答上的配额种类字节 8（RateLimit），TCP 线格式不变。

再平衡会隔离源，并返回一个空的目标目录。故障域隔离会移除该域中的成员，并拒绝移除最后一个成员。这些操作都不拷贝载荷字节。

这棵树不操作这些事：不格式化 NVMe，不改 DPU 模式，不动固件，不改 IOMMU 或 BIOS，不改生产网络。G4 的在线调用保持由环境变量开关。如果以后有人用 Soft-RoCE 做冒烟，它也只是功能冒烟，不是性能数字。

定位和分层分工见 介绍手册。上游细节：OPERATIONS.md 和 README.md。
