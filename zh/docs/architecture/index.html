架构

GPUCache 是 G3.5 共享 KV 热层。当前实现使用主机内存和 TCP；RustFS 是更冷的 G4 对象层，不位于热请求路径中。

开发中

BlueField-3、GDS 和真实 RDMA 仍在开发中，状态为 NOT_RUN_HARDWARE。当前路径包含主机拷贝，不宣称零拷贝或绕过 CPU。

当前可运行的路径

Rust 服务通过 TCP 提供 Lookup、Reserve/Put、Commit、Get、Release/Cancel 和 Invalidate。MemoryStore 与 FileStore 是 CPU 后端，FileStore 使用普通文件。TCP 的每个数据操作都会执行授权检查，但未实现 mTLS。

先验证身份，再复用

只有已提交且租户、信任域、模型和完整布局身份兼容的块才能命中。前缀命中返回整个已存储块，不会静默切分块内数据。未命中、超时和校验失败都回退到重新计算。

单节点与多分片

单进程可以作为一个分片，客户端操作保持一致。目录只保存有界元数据；客户端限制路由、连接和重试记录数量。成员变更会隔离在途操作。运维方发布经过 fencing 的 epoch 快照；自动发现与共识尚未实现。

冷层独立运行

G4 打包与回填使用 v3 清单、内容摘要键和完整身份校验；旧清单返回未命中。冷层缓慢或不可用时返回 Missing。失败写入任务保留有界额度；PUT 结果不确定时不会触发 DELETE。mock 测试已可运行，真实 RustFS 为 NOT_RUN_HARDWARE。

DPU 目标

HostSimulation 覆盖类型化消息、取消、故障与显式排空。rdma-nixl 和 dpu-bf3 特性不链接设备 SDK，设备打开操作会明确拒绝。aarch64 CPU 构建不等于 BlueField 卸载。真实引擎导出／导入尚未验证，engine-spike 仅使用伪造块。

故障意味着重新计算

G3.5 不增加纠删码或持久性副本。传输完成状态未知时保持隔离，只有显式排空或更新的 fence 才能允许复用。冷数据持久性归 RustFS；这是缓存契约，不是灾备，也不是集群规模验证。
