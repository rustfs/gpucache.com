介绍使用架构分层路线图快速开始

GPUCache / 文档 / 架构

文档 开发中

架构

GPUCache 把 KV 数据的热路径放在网卡、DPU 和 SSD 之间。下面写的是设计目标。

开发中

BlueField-3 支持、DPU 与 GDS 直通路径，以及和 vLLM、TensorRT-LLM 的对接，都在开发中。

主分支上有什么

主分支包含 CPU/TCP 契约：V1 A/B/C，V2 切片（TCP、分片本地目录、mock 冷路径），以及 V3 桩（DPU 特性门和加固钩子）。能跑的是这份 CPU 契约。BlueField-3、GDS、DPU 硬件路径，以及真实的 RDMA/NIXL 性能，是「开发中」，并标为 NOT_RUN_HARDWARE。Soft-RoCE 只做功能冒烟，不是性能数字。

没有纠删码，热层也没有持久副本。G3.5 未命中或节点丢失是一次干净的未命中：重算，再写回。冷数据由 G4 的 RustFS 保存。本页的图仍是硬件路径的设计目标。请读 介绍手册 和 使用手册。

三个角色

  • GPU 放正在生成时用到的 KV，并取回需要的 KV。
  • DPU 运行 Rust KV 引擎，管理闪存。BlueField-3 支持开发中。
  • 闪存 共享 NVMe，存放集群可以复用的 KV。

数据路径

下面这条线是设计目标，不是今天已经跑起来的路径。第一阶段要打通的是经主机内存的路径。

  1. GPU 显存 / 主机内存
  2. RDMA / RoCEv2
  3. DPURust KV 引擎
  4. SPDK
  5. NVMe 闪存

开发中

三级都在开发中

  1. 主机内存路径 KV 在主机 DRAM 和 DPU、闪存之间传输。这是第一阶段要打通的基线。
  2. 暂存路径 GPU 显存的数据先经过一次暂存，再交给 DPU。这是过渡形态，暂存必须可观测。
  3. GDS 直通 GPU 显存经 DPU 直达闪存，没有主机暂存。这是 GPUCache 的目标形态。

只有拿到运行时证据之后，公开材料才能写「支持 GDS 直通」：实际走了直通路径、没有回退或静默暂存、两端字节和校验一致。不能因为接口或设备类型就这么写。

组件

  1. 01

    Rust KV 引擎 开发中

    面向 KV Cache 的存储引擎，用 Rust 编写，运行在 DPU 的 Arm 核上。

  2. 02

    RDMA / RoCEv2 传输 开发中

    计算节点与 G3.5 之间走 RDMA 通信。

  3. 03

    SPDK 闪存管理 开发中

    在 DPU 上用 SPDK 直接访问 NVMe SSD。

  4. 04

    NVIDIA DOCA 与 Arm 交叉编译 开发中

    在 BlueField-3 上构建和运行。

  5. 05

    推理框架对接 开发中

    计划对接 vLLM、TensorRT-LLM 等推理框架的 KV Cache 接口（按 PagedAttention 的块粒度管理）。

CPU 的边界

准确说法是「存储侧不需要 x86 存储主机，KV 数据的热路径不经过主机 CPU 转发」。计算节点上仍要保留注册内存、提交请求、收取完成事件这类最小状态。

丢失意味着什么

GPUCache 不承担数据持久性。G3.5 节点故障或数据丢失时，推理框架拿到的是一次 miss，按原来的方式重算预填充，再写回 GPUCache，下次就能命中。

需要长期保存的上下文和产物存到 G4 的 RustFS。RustFS 是容量层，GPUCache 是热层。

不适合的场景

  • 需要持久保存的数据。G3.5 是缓存，持久数据放 G4 RustFS。
  • 训练场景的 checkpoint 存储。那是 G4 的工作。
  • 想现在就部署到生产环境。CPU 契约可以从源码跑；硬件路径仍是「开发中」，这棵树也不是生产就绪。
