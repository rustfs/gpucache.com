RUSTFS GPUCACHE · G3.5 En développement

Un cache KV partagé au niveau G3.5.

GPUCache est le niveau chaud G3.5 de KV partagé. Le chemin implémenté utilise la mémoire hôte et TCP. RustFS constitue le niveau objet G4, plus froid, hors du chemin des requêtes chaudes.

GPUCache est en G3.5 : plus simple à partager qu'un SSD local au nœud, et plus proche du chemin chaud d'inférence qu'un stockage partagé. G4 est tenu par RustFS.

Problème

Quand le contexte est évincé, le GPU doit recalculer.

Un long contexte, un dialogue à plusieurs tours et les agents font grossir le KV Cache jusqu'à ce que la mémoire GPU ne puisse plus le contenir. Quand un KV évincé sert de nouveau, il faut refaire le préremplissage : le GPU dépense des cycles sur un travail déjà fait, et le premier token attend plus longtemps.

Chaque couche existante a une limite. La mémoire hôte est finie. Un SSD local au nœud ne sert qu'une machine et se partage mal entre nœuds. Le stockage partagé est fait pour la durabilité et la capacité, et il n'est pas sur le chemin chaud d'inférence.

Approche

Réutiliser les blocs compatibles, recalculer sur un miss.

BlueField-3, GDS et RDMA réel sont des objectifs en développement : NOT_RUN_HARDWARE. Le chemin actuel copie des données sur l’hôte et ne revendique ni zéro copie ni contournement du CPU.

  1. 01

    Le chemin exécutable aujourd’hui

    CPU/TCP et les backends mémoire et fichiers sont disponibles en source. Aucun GPU ni DPU requis.

  2. 02

    Un nœud ou plusieurs shards

    Routes, connexions et fencing des epochs bornés permettent des shards gérés par l’opérateur.

  3. 03

    Une perte entraîne un recalcul

    G3.5 n’ajoute ni codage d’effacement ni réplica de durabilité. Un transfert dont la fin est inconnue reste en quarantaine jusqu’à un drain explicite ou une clôture plus récente autorisant sa réutilisation. RustFS assure la durabilité des données froides. C’est un contrat de cache, pas une reprise après sinistre ou une qualification à l’échelle d’une flotte.

Ce qui ne convient pas

  • Des données qui doivent rester. G3.5 est un cache. Les données durables vont sur RustFS en G4.
  • Le stockage des checkpoints d'entraînement. C'est le travail de G4.
  • Le déploiement en production n’est pas encore qualifié.

Comment lire cette feuille de route

Avec RustFS

G3.5 garde ce qui est chaud. G4 garde ce qui doit durer.

Découvrir RustFS

GPUCache est construit par l'équipe RustFS. Les deux ont un partage clair dans la hiérarchie de stockage. GPUCache est la couche chaude G3.5, proche du GPU et faite pour la réutilisation. RustFS est la couche de capacité G4, un stockage objet distribué compatible S3 écrit en Rust, chargé de garder modèles, jeux de données, historique de session et produits d'inférence.

Une couche chaude perdue peut être recalculée. Les données de la couche de capacité ne doivent pas se perdre. Séparer les deux tâches rend chacune plus simple.

Démarrage En développement

Compiler, tester et examiner le contrat CPU.

La branche main contient du code Rust exécutable pour le cache KV partagé G3.5 sur CPU/TCP. Commencez par les tests de contrat logiciel ; aucun GPU ni DPU n’est nécessaire.

Le code source est disponible. Il n’existe pas encore de version installable ni de qualification pour la production.

  1. Installer Rust stable avec Cargo, Git et Python 3.
  2. Cloner les sources et lancer les tests du workspace.
  3. Suivre le guide complet pour les démos et la régression CPU.
git clone https://github.com/rustfs/GPUCache.git
cd GPUCache
cargo test --workspace --all-targets
cargo run -p gpucache-transport --bin share-demo

Le guide complet inclut la régression CPU et les limites matérielles explicites. Compiler et tester depuis les sources
