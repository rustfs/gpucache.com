Utilisation

Manuel d'utilisation

Ces étapes exécutent le contrat CPU et TCP depuis une extraction propre. Elles n'installent pas de paquet, ne formatent pas un disque et n'ouvrent pas un DPU. BlueField-3, GDS, le chemin matériel DPU et une performance RDMA ou NIXL réelle restent en développement.

En développement

Il n'y a pas de déploiement de production et pas de publication crates.io. Soft-RoCE est un smoke fonctionnel seulement, pas un chiffre de performance. Un miss G3.5 ou un nœud perdu est un miss propre : recalcul, puis réécriture. Pas d'erasure coding et pas de réplica de durabilité sur le tier chaud. RustFS est le tier froid G4.

Installation

rust-toolchain.toml sélectionne Rust stable. Le MSRV déclaré est 1.85. Il n'y a pas de paquet installable. Clonez le dépôt et lancez les tests du contrat CPU :

git clone https://github.com/rustfs/GPUCache.git
cd GPUCache
cargo test --workspace --all-targets

cargo test --workspace --all-targets est la repro CPU en une commande pour V1 A, V1 B et V1 C, et couvre aussi les tests CPU V2 et V3 présents dans l'arbre. Les octets sont synthétiques. Ce n'est pas un tenseur KV vLLM, et la commande n'est pas un résultat de bande passante. La CI exécute aussi cargo fmt --all -- --check et cargo clippy --workspace --all-targets -- -D warnings.

Démarrage

Le service TCP écoute le loopback tant que vous ne l'ouvrez pas. Le bind par défaut est 127.0.0.1:9735. Une adresse hors loopback exige --allow-remote. Ce drapeau ne coupe pas l'authentification. Le processus exige encore une empreinte d'identifiant de tenant : 32 octets, en hexadécimal, pas tout à zéro. Passez le hachage, pas un secret vivant. Il n'y a pas de chemin de données non authentifié.

cargo run -p gpucache-transport --bin gpucache-tcp -- serve --data-dir /tmp/gpucache-dev --tenant tenant-a --trust td-local --fingerprint <64 hex chars of a credential hash>

--data-dir est un répertoire de fichiers ordinaires (MANIFEST, LRU et blocks/*.gblk). Ne le pointez pas vers un nœud de périphérique. Le processus ne formate pas le NVMe, ne change pas une NIC et ne touche pas un DPU. Il n'y a pas de fichier de configuration sur disque. Les drapeaux sont le schéma. Cet exemple est un loopback de développement seulement.

Démos

Chaque bannière est un contrôle de correction. Aucune n'est un chiffre de performance. BlueField-3, GDS et le RDMA en direct restent NOT_RUN_HARDWARE.

CommandeBannière de succèsCe que c'est
cargo run -p gpucache-transport --bin share-demostatus=REUSE_OK et partial_prefix=WHOLE_BLOCK_PREFIXDeux clients localhost partagent un service sur fichiers. La chaîne plus longue réutilise le bloc plus court en entier. Une valid_length plus courte n'est pas découpée. intra_block_slice=DEGRADED_MISS.
cargo run -p gpucache-transport --bin fault-demostatus=FALLBACK_OK, criteria=EXACT_TOKEN_IDS, tolerance=NONEHit, miss, fichier corrompu, échéance, annulation et refus de quota échouent fermé. L'appelant recalcule. Un mauvais tenant ou un mauvais modèle n'est pas un hit. Pas une exécution vLLM.
cargo run -p gpucache-transport --bin shard-demostatus=SHARD_OK, registration=SIMULATED, rdma=NOT_RUN_HARDWAREUn shard, clôture d'époque, quarantaine au-delà du bail, et une copie hôte TCP. Pas un enregistrement NIC.
cargo run -p gpucache-cold --bin cold-demostatus=COLD_CONTRACT_OK et gds=NOT_RUN_HARDWAREPack, sink et refill plafonné du mock G4. rustfs_live=NOT_RUN_HARDWARE sans point d'accès configuré.

kv-block-xfer lit une trame GEXP sur stdin et l'importe dans un MemoryStore neuf. Il imprime status=IMPORTED seulement après un lookup et un get réussis. Un échec de somme de contrôle sort avec le code 2. Il ne parle pas à un moteur.

cargo run -p gpucache-storage --bin kv-block-xfer -- import <64 hex chars of a credential hash>

Configuration

Il n'y a pas de fichier de configuration. Les drapeaux du binaire et ResourceLimits::dev_defaults() sont le schéma.

ChampDéfautSens
bind127.0.0.1:9735Socket. Hors loopback, allow_remote est requis. Les tests utilisent le port 0.
data_dirRequisRépertoire de fichiers ordinaires. Pas un nœud de périphérique.
tenant, trust, fingerprintRequisUne politique V1. L'empreinte fait 32 octets et n'est pas toute à zéro.
allow_remotefalseNe désactive pas l'auth.
max_connections16Les connexions en trop sont abandonnées.
max_frame_bytes1 MiB dans la bibliothèque, 2 MiB dans le binairePlafond du corps. Une longueur déclarée plus grande est refusée avant la lecture.
pool_buffers16Pool de tampons de lecture. Le retrait échoue au plafond.
io_timeout5 sDélai de lecture et d'écriture sur chaque connexion.

Laissez GPUCACHE_RUSTFS_ENDPOINT, GPUCACHE_RUSTFS_BUCKET, GPUCACHE_RUSTFS_PREFIX, GPUCACHE_RUSTFS_ACCESS_KEY et GPUCACHE_RUSTFS_SECRET_KEY non définis tant qu'un opérateur n'a pas autorisé un bucket de test. Non défini veut dire NOT_RUN_HARDWARE. N'inventez pas d'identifiants. https:// est NOT_RUN_HARDWARE dans cette étape parce qu'aucune pile TLS n'est liée.

Quotas

ResourceLimits borne la taille d'objet, les requêtes en vol, les enregistrements (y compris les tampons commités et en quarantaine), les octets en vol par tenant, les octets retenus globaux et les octets retenus par tenant. La table d'idempotence est plafonnée et les entrées expirent.

MemoryStore refuse l'admission au lieu d'évincer. FileStore évince le plus ancien bloc commité non épinglé quand un quota d'octets retenus échouerait. Il n'évince pas un autre tenant pour satisfaire un quota de tenant, et il n'évince pas un bloc épinglé ou en quarantaine. Invalidate est le chemin explicite du client.

Les crédits de shard, le plafond de slab simulé, la rétention froide et le budget d'octets de backfill sont des plafonds d'admission pour du KV recalculable. Ce n'est pas une taille de cluster mesurée. Ne dimensionnez pas le tier chaud comme la seule copie des données utilisateur.

Pannes et miss

GPUCache est le tier chaud partagé G3.5. RustFS est le tier froid G4. Sur un miss G3.5 ou une perte de nœud, le résultat est un miss propre, puis un recalcul, puis une réécriture. Il n'y a pas d'erasure coding et pas de réplica de durabilité sur le tier chaud.

  • Un hit est seulement un bloc COMMITTED d'identité compatible dont la somme correspond encore.
  • ABSENT, RESERVED, WRITING, EVICTING et QUARANTINED ne renvoient pas de charge utile.
  • Miss, délai, échec de somme, écart de version, panne du store, refill au-dessus du budget, époque clôturée, fichier corrompu ou tronqué, et erreur de transport sont des recalculs. Aucun n'est un hit réussi.
  • Un mauvais tenant, modèle, tokenizer, adaptateur ou une mauvaise disposition n'est pas un hit. Un hit faux est une panne.
  • Une valid_length plus courte sur la même chaîne de hachage est un miss incompatible. Le service ne découpe pas l'intérieur d'un bloc.
  • L'expiration du bail ne prouve pas qu'une copie s'est arrêtée. Une région en quarantaine reste jusqu'à une attestation de vidage ou une époque clôturée plus récente.
  • Un redémarrage recharge les fichiers commités, augmente l'époque et abandonne les réservations en vol.
  • Les décisions de dégradation pour redémarrage DPU, reset GPU, flap NIC, perte de stockage, délai NVMe, perte du plan de contrôle, et RustFS lent ou arrêté, sont des miss propres. Ce tableau n'est pas une injection de faute matérielle. Pas de charge utile, pas de hit faux, pas de blocage permanent.

Le moteur peut réécrire le bloc recalculé par la même API de lot. Le tier chaud ne répare pas lui-même le bloc perdu.

Notes d'exploitation

dpu-demo est l'esquisse de diagnostic. Il imprime si dpu-bf3 a été choisi, que DOCA, SPDK et NVMe ne sont pas liés, que l'erasure coding du tier chaud est coupé, et que chaque cible prévue est NOT_RUN_HARDWARE. Il n'imprime ni charge utile, ni empreinte, ni prompt. Il n'y a pas de compteur de santé de périphérique parce qu'aucun périphérique n'est ouvert.

ControlPlane::begin_upgrade arrête les nouveaux remplissages. Les remplissages en vol peuvent encore finir. rollback avant finish revient au service sans clôture. finish_upgrade augmente une génération logicielle et clôture, donc les anciennes époques manquent et le moteur recalcule. rollback après finish clôture à nouveau. Le compteur de génération ne diminue pas. Aucun firmware BlueField, BFB ou paquet DOCA ne fait partie de ce rollback. Le format fil TCP est inchangé, à part l'octet 8 de type de quota (RateLimit) sur les réponses d'erreur.

Le rééquilibrage clôture la source et renvoie un répertoire de destination vide. L'isolation de domaine de faute retire les membres de ce domaine et refuse de retirer le dernier membre. Aucune de ces actions ne copie d'octets de charge.

Non opéré depuis cet arbre : pas de format NVMe, pas de changement de mode DPU, pas de firmware, pas de changement IOMMU ou BIOS, pas de changement du réseau de production. Les appels G4 en direct restent gardés par l'environnement. Soft-RoCE, si quelqu'un l'exerce plus tard comme smoke, est un smoke fonctionnel seulement et n'est pas un chiffre de performance.

La position et le partage des tiers sont dans le manuel d'introduction. Détail amont : OPERATIONS.md et README.md.
