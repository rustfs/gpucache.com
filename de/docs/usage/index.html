GPUCache / Dokumentation / Nutzung

Nutzung

Nutzung

Diese Schritte führen den CPU- und TCP-Vertrag aus einem sauberen Checkout aus. Sie installieren kein Paket, formatieren keine Platte und öffnen keinen DPU. BlueField-3, GDS, der DPU-Hardwarepfad und echte RDMA- oder NIXL-Leistung bleiben in Entwicklung.

In Entwicklung

Es gibt kein Produktions-Deploy und keine Veröffentlichung auf crates.io. Soft-RoCE ist nur ein funktionaler Smoke-Test, keine Leistungszahl. Ein G3.5-Fehltreffer oder ein verlorener Knoten ist ein sauberer Fehltreffer: neu berechnen, dann zurückschreiben. Kein Erasure Coding und kein Haltbarkeitsreplikat auf der heißen Schicht. RustFS ist die kalte G4-Schicht.

Installation

rust-toolchain.toml wählt Rust stable. Die erklärte MSRV ist 1.85. Es gibt kein installierbares Paket. Klonen Sie das Repository und führen Sie die CPU-Vertragstests aus:

git clone https://github.com/rustfs/GPUCache.git
cd GPUCache
cargo test --workspace --all-targets

cargo test --workspace --all-targets ist die Ein-Befehl-CPU-Repro für V1 A, V1 B und V1 C und deckt auch die V2- und V3-CPU-Tests in diesem Baum ab. Die Bytes sind synthetisch. Sie sind kein vLLM-KV-Tensor, und der Befehl ist kein Bandbreitenergebnis. CI führt außerdem cargo fmt --all -- --check und cargo clippy --workspace --all-targets -- -D warnings aus.

Start

Der TCP-Dienst lauscht auf Loopback, solange Sie das nicht öffnen. Der Default-Bind ist 127.0.0.1:9735. Eine Adresse außerhalb von Loopback braucht --allow-remote. Das Flag schaltet Authentisierung nicht ab. Der Prozess verlangt weiter einen Fingerabdruck der Tenant-Credential: 32 Bytes, hexadezimal, nicht nur Nullen. Übergeben Sie den Hash, kein lebendes Geheimnis. Es gibt keinen unauthentisierten Datenpfad.

cargo run -p gpucache-transport --bin gpucache-tcp -- serve --data-dir /tmp/gpucache-dev --tenant tenant-a --trust td-local --fingerprint <64 hex chars of a credential hash>

--data-dir ist ein Verzeichnis gewöhnlicher Dateien (MANIFEST, LRU und blocks/*.gblk). Zeigen Sie nicht auf einen Geräteknoten. Der Prozess formatiert kein NVMe, ändert keine NIC und berührt keinen DPU. Es gibt keine Konfigurationsdatei auf der Platte. Die Flags sind das Schema. Dieses Beispiel ist nur ein Entwicklungs-Loopback.

Konfiguration

Es gibt keine Konfigurationsdatei. Die Binary-Flags und ResourceLimits::dev_defaults() sind das Schema.

FeldDefaultBedeutung
bind127.0.0.1:9735Socket. Außerhalb von Loopback braucht es allow_remote. Tests nutzen Port 0.

Lassen Sie GPUCACHE_RUSTFS_ENDPOINT, GPUCACHE_RUSTFS_BUCKET, GPUCACHE_RUSTFS_PREFIX, GPUCACHE_RUSTFS_ACCESS_KEY und GPUCACHE_RUSTFS_SECRET_KEY ungesetzt, solange kein Operator einen Test-Bucket freigegeben hat. Ungesetzt heißt NOT_RUN_HARDWARE. Erfinden Sie keine Zugangsdaten. https:// ist in diesem Meilenstein NOT_RUN_HARDWARE, weil kein TLS-Stack gelinkt ist.

Quoten

ResourceLimits begrenzt Objektgröße, laufende Anfragen, Registrierungen (einschließlich committeter und quarantänisierter Puffer), In-Flight-Bytes je Tenant, global behaltene Bytes und behaltene Bytes je Tenant. Die Idempotenztabelle ist gedeckelt, Einträge laufen ab.

MemoryStore lehnt die Aufnahme ab, statt zu evicten. FileStore evictet den ältesten nicht gepinnten committeten Block, wenn eine Quote behaltener Bytes scheitern würde. Es evictet keinen anderen Tenant, um eine Tenant-Quote zu erfüllen, und keinen gepinnten oder quarantänisierten Block. Invalidate ist der explizite Client-Pfad.

Shard-Credits, die simulierte Slab-Grenze, kalte Retention und das Backfill-Bytebudget sind Aufnahmegrenzen für neu berechenbares KV. Sie sind keine gemessene Clustergröße. Dimensionieren Sie die heiße Schicht nicht als die einzige Kopie von Nutzerdaten.

Fehler und Fehltreffer

GPUCache ist die gemeinsame heiße Schicht auf G3.5. RustFS ist die kalte Schicht auf G4. Bei einem G3.5-Fehltreffer oder Knotenverlust ist das Ergebnis ein sauberer Fehltreffer, dann Neuberechnung, dann Zurückschreiben. Es gibt kein Erasure Coding und kein Haltbarkeitsreplikat auf der heißen Schicht.

  • Ein Treffer ist nur ein COMMITTED-Block mit kompatibler Identität und einer Prüfsumme, die noch passt.
  • ABSENT, RESERVED, WRITING, EVICTING und QUARANTINED liefern keine Nutzdaten.
  • Fehltreffer, Timeout, Prüfsummenfehler, Versionsabweichung, Speicherausfall, Refill über Budget, eingezäunte Epoche, beschädigte oder abgeschnittene Datei und Transportfehler sind Neuberechnungen. Keiner davon ist ein erfolgreicher Treffer.
  • Falscher Tenant, falsches Modell, falscher Tokenizer, falscher Adapter oder falsches Layout ist kein Treffer. Ein falscher Treffer ist ein Fehler.
  • Eine kürzere valid_length auf derselben Hash-Kette ist ein inkompatibler Fehltreffer. Der Dienst schneidet nicht innerhalb eines Blocks.
  • Ablauf der Lease beweist nicht, dass eine Kopie gestoppt hat. Eine quarantänisierte Region bleibt bis zur Drain-Bestätigung oder einer neueren eingezäunten Epoche.
  • Ein Neustart lädt committete Dateien neu, hebt die Epoche an und verwirft laufende Reservierungen.
  • Die Degrade-Entscheidungen für DPU-Neustart, GPU-Reset, NIC-Flap, Speicherverlust, NVMe-Timeout, Verlust der Control Plane und langsames oder ausgefallenes RustFS sind saubere Fehltreffer. Diese Tabelle ist keine Hardware-Fehlerinjektion. Keine Nutzdaten, kein falscher Treffer, keine dauerhafte Blockade.

Die Engine kann den neu berechneten Block über dieselbe Batch-API zurückschreiben. Die heiße Schicht repariert den verlorenen Block nicht selbst.

Betriebshinweise

dpu-demo ist die Diagnose-Skizze. Es druckt, ob dpu-bf3 gewählt wurde, dass DOCA, SPDK und NVMe nicht gelinkt sind, dass Erasure Coding auf der heißen Schicht aus ist, und dass jedes geplante Ziel NOT_RUN_HARDWARE ist. Es druckt keine Nutzdaten, Fingerabdrücke oder Prompts. Es gibt keinen Geräte-Gesundheitszähler, weil kein Gerät offen ist.

ControlPlane::begin_upgrade stoppt neue Fills. Laufende Fills können noch enden. rollback vor finish kehrt ohne Zaun zum Dienst zurück. finish_upgrade hebt eine Software-Generation an und zäunt ein, sodass alte Epochen fehlen und der Engine neu berechnet. rollback nach finish zäunt erneut ein. Der Generationszähler sinkt nicht. BlueField-Firmware, BFB oder ein DOCA-Paket gehören nicht zu diesem Rollback. Das TCP-Wire-Format bleibt unverändert, außer Quota-Kind-Byte 8 (RateLimit) auf Fehlerantworten.

Rebalance zäunt die Quelle ein und gibt ein leeres Zielverzeichnis zurück. Fault-Domain-Isolation entfernt Mitglieder dieser Domain und weigert sich, das letzte Mitglied zu entfernen. Keines davon kopiert Nutzdaten.

Aus diesem Baum nicht betrieben: kein NVMe-Format, kein DPU-Moduswechsel, keine Firmware, keine IOMMU- oder BIOS-Änderung, keine Änderung am Produktionsnetz. Live-Aufrufe auf G4 bleiben über Umgebungsvariablen gegated. Soft-RoCE, falls es später jemand als Smoke-Test ausführt, ist nur ein funktionaler Smoke-Test und keine Leistungszahl.

Position und Schichttrennung stehen in der Einführung. Upstream-Detail: OPERATIONS.md und README.md.
