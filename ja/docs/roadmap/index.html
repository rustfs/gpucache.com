ロードマップ

利用可能なソースと再現可能な CPU 契約を、実機の検証と区別します。リリース日や実測クラスタ容量を約束するものではありません。

状況機能検証の境界
CPU/TCP 利用可能識別情報、ライフサイクル、MemoryStore/FileStore、TCP ACL、読み取りの受付制限合成データのテスト。信頼されたネットワークが前提で、mTLS は未実装。
CPU/TCP 利用可能有界シャードクライアント、メンバー更新、epoch フェンシング運用者が経路を管理。分散合意や実運用規模の認証は未実施。
mock 契約が利用可能G4 v3 マニフェスト、有界キュー、リフィル、保持管理実際の RustFS は NOT_RUN_HARDWARE。孤立オブジェクトの回収は自動化しない。
CPU シミュレーションDPU メッセージ、障害注入、TCP との機能比較デバイスオフロード、ゼロコピー、スループット、TCO の実証ではない。
偽ブロックの実験EngineBlockContract と engine-spike実 vLLM の入出力は NOT_RUN_HARDWARE。GPU／モデル実行は NOT_RUN_BUDGET。
開発中実 RDMA、GDS、BlueField-3 / DOCA、SPDKNOT_RUN_HARDWARE。オプション機能は機器をリンクせず、オープンを拒否。

次に必要な検証

承認済みの GPU とモデル資源で実エンジンを検証し、適切な対照条件で実機経路を測定します。それまでは TCO_UNKNOWN と NOT_EVALUATED を維持します。ソースが利用できても、インストール可能なリリースや本番対応を意味しません。

維持する境界

RustFS はホット経路に入りません。G3.5 の損失時は再計算し、消失訂正符号や永続レプリカは計画しません。拡張は有界シャード、フェンシング、安全なミスに基づき、10,000 GPU を検証済みとは主張しません。
