紹介

紹介マニュアル

GPUCache は G3.5 の共有 KV ホット層です。RustFS はより冷たい G4 の容量層です。このツリーで実行できるのは CPU と TCP の契約です。BlueField-3、GDS、DPU のハードウェア経路、そして実 RDMA / NIXL の性能は、いずれも開発中です。

実装済み開発中

V1 A/B/C と V2 の CPU スライスは main にあります。V3 は DPU のフィーチャーゲートと、本番向け硬化のスタブです。ハードウェア経路は NOT_RUN_HARDWARE を出します。Soft-RoCE は機能スモークだけで、性能値ではありません。

位置づけ動くものアーキテクチャG3.5 と G4同じプロトコル

製品の位置づけ

GPUCache は、分離推論向けのオープンな共有 KV キャッシュ層です。NVIDIA CMX の用語では、この層が G3.5 です。GPU HBM の手前にあり、同じテナント、同じモデル、同じレイアウトの要求で再利用します。RustFS は G4 の容量バックエンドです。G4 は prefill から decode へのホットパスには乗りません。

KV ブロックは再計算できるアクセラレータ状態です。利用者のプロンプトの唯一のコピーではなく、モデルに依存しない長期記憶でもありません。トークン化、アテンション、スケジューリングは推論エンジンの仕事のままです。このリポジトリはそれらを置き換えません。

ミス、タイムアウト、チェックサム不一致、バージョン不一致、ストア停止は、エンジンへ戻します。エンジンは再計算し、ブロックを書き戻すことができます。誤ったヒットは故障です。インストールできるパッケージはなく、本番配置もなく、測ったクラスタ規模もありません。このツリーを PB 級や本番準備完了とは書かないでください。

ライセンスは Apache 2.0 です。公開文は main の README と、その隣のドキュメントに従います。

動くものと、開発中のもの

既定のビルドは CPU と TCP です。DOCA、CUDA、RDMA、NIXL、SPDK はリンクしません。aarch64 ビルドは CPU ビルドであり、BlueField の機能試験ではありません。フィーチャー rdma-nixl は libnixl をリンクしません。フィーチャー dpu-bf3 はデバイスをリンクしません。NixlTransport::open、open_doca、open_nvme_device、open_spdk は拒否します。

項目状態意味
V1 A/B/C の CPU 契約実装済みアイデンティティ、プロトコル、MemoryStore、TCP サービス、ファイルバックエンド、LRU 受付、テナントクォータ、ファズ、障害試験。バイトは合成です。実 vLLM の KV エクスポートは NOT_RUN_HARDWARE です。
V2：TCP、シャードディレクトリ、コールド経路実装済みTCP が既定のトランスポートです。登録は模擬プールであり、NIC ではありません。1 プロセスが 1 シャードです。G4 のパックとリフィルはモックに対して動きます。オペレータが GPUCACHE_RUSTFS_* を置かない限り、ライブ RustFS は NOT_RUN_HARDWARE です。
V3：DPU ゲートと硬化スタブ開発中CPU 側の認可、リプレイ、クォータ、コールド操作のフックはツリーにあります。リバランスとローリングアップグレードはフィルをフェンスし、レプリカはコピーしません。デバイスはリンクされません。dpu-demo は NOT_RUN_HARDWARE を出します。
BlueField-3、GDS、DPU ハードウェア経路開発中常に開発中です。実装済みでも、配備済みでも、測った本番経路でもありません。
実 RDMA / NIXL の性能開発中ライブ RDMA は NOT_RUN_HARDWARE です。対になった TTFT、TPOT、TCO は公表しません。tco=TCO_UNKNOWN。go_gate=NOT_EVALUATED。TCP は DPU の基準線ではありません。
Soft-RoCEスモークのみSoft-RoCE は機能スモークだけです。性能値ではなく、このサイトもその数字を出しません。
エンジン統合開発中経路は未選定です。ネイティブ vLLM KV connector か LMCache かは決まっていません。第二エンジンは追加していません。
イレイジャーコーディングとホット層レプリカこの製品には無い作りません。ホット層のイレイジャーコーディングは有効にできません。失ったホットブロックはクリーンミスです。

コマンド、成功バナー、各デモの限界は 利用マニュアル にあります。

アーキテクチャ

ホームの図は DPU 経路の設計目標です。このツリーはその経路を実行していません。実行できる形は次です。

engine (not in this tree; NOT_RUN_HARDWARE)
        |  CacheIdentity + batch API
        v
gpucache-transport    TCP, loopback by default
        v
FileStore             ordinary files in a directory you pass
        v
MemoryStore           in-process contract
gpucache-cold         optional G4 mock. Not on the TCP hot path.
gpucache-dpu          simulated queue. Not on the TCP hot path.
  • gpucache-core-types は、版付き CacheIdentity、長さ区切りの論理キーと物理キー、ブロックのライフサイクル、チェックサム、クォータ、エラーを持ちます。
  • gpucache-protocol は、バッチメッセージ、期限、テナント認証コンテキスト、ワイヤ版の交渉を持ちます。
  • gpucache-storage は MemoryStore、FileStore、kv-block-xfer を持ちます。FileStore はディスクをフォーマットせず、デバイスノードも開きません。
  • gpucache-transport は TCP の正しさの経路に、模擬の登録バッファプールとシャードローカルなディレクトリを足したものです。
  • gpucache-cold はマニフェストをパックし、トレイト経由で Put、Head、RangeGet、Delete ができます。トランスポートはこれに依存しません。
  • gpucache-dpu は BlueField のフィーチャースロットです。ホットパスはこれを呼びません。
  • gpucache-bench は対の基準線の名前を出し、NOT_RUN_HARDWARE を印字します。時間を作ってはいけません。

ヒットになるのは、アイデンティティが互換で、保存したチェックサムがバイトとまだ一致する COMMITTED ブロックだけです。ABSENT、RESERVED、WRITING、EVICTING、QUARANTINED は読めません。

ABSENT -> RESERVED -> WRITING -> COMMITTED -> EVICTING -> ABSENT
                 \-> QUARANTINED -> ABSENT

失敗またはタイムアウトした登録領域は QUARANTINED になります。リース期限では解放しません。回収には、認可されたドレイン証明か、領域をフェンスする新しいエポックが要ります。レイアウトと、バイトに影響する他のフィールドが一致すれば、より長いハッシュ鎖は、より短いコミット済みブロック全体に対して PrefixHit を返せます。サービスはブロックの内側を切りません。同じ鎖のより短い valid_length は非互換ミスです。

生のプロンプト、トークン ID、メディアバイトはアイデンティティのフィールドではありません。呼び出し側がストアの外でハッシュします。同じトークンが同じバイトを意味するわけではありません。論理プレフィックスキーと物理バイトキーは別の符号化です。再利用は 1 テナント、1 モデル、1 レイアウトの中だけです。リシャード、量子化、レイアウト不一致はミスです。テナントをまたぐ重複排除はありません。

G3.5 と G4

G3.5 の GPUCache は共有ホット層です。G4 の RustFS は冷たい容量層です。ホット層は失ったブロックを修復しません。イレイジャーコーディングはなく、ホット層の耐久レプリカもありません。喪失、破損、短い書き込み、ディスク満杯、退避、検査失敗はクリーンミスです。エンジンが再計算し、ブロックを書き戻せます。

メモリ上のコミットのあとディスク書き込みが失敗した場合、そのコミットは捨てられ、request id も忘れられます。保存されていないバイトを、リプレイが成功と報告することはありません。ホットな共有プレフィックスの追加コピーが将来あっても、それは遅延のヒントです。このツリーには無く、耐久の約束にもなりません。

冷データの耐久は RustFS の仕事です。TCP サービスはコールドクレートを呼びません。予算超過のリフィルや、遅い、あるいは落ちている RustFS はペイロードを返しません。その結果は再計算であり、ヒットではありません。ライブバケットへの https:// は、TLS スタックをリンクしていないため、ここでは NOT_RUN_HARDWARE です。オペレータがテストバケットを認可していない限り、GPUCACHE_RUSTFS_* は未設定のままにしてください。

単一ノードから分散へ、プロトコルは同じ

実行できる経路のバッチ API は同じです。Lookup、Reserve/Put、Commit、Get、Release/Cancel、Invalidate。各項目は request_id、エポック、期限を持ち、当てはまるときは世代、長さ、チェックサムも持ちます。

MemoryStore はプロセス内のシングルスレッド契約です。TCP サービスは同じ API を出します。シャード 0 が単一ノードの場合で、他のシャードと同じ ShardDirectory のメソッドを使います。1 プロセスが 1 シャードです。トークン単位の中央ディレクトリはなく、ブロック単位のクォーラムもありません。メンバー変更はエポックを上げ、進行中のフィルを落とし、クレジットを返します。シングルフライトの参加者は二度目のクレジットを取らず、ディレクトリからペイロードバイトを受け取りません。

このツリーで、1 ノードから分散層へ進む段はそれだけです。同じプロトコル、同じディレクトリメソッド、依然として 1 プロセス 1 シャード。シャードをまたぐ形は別のワイヤプロトコルではなく、動いているクォーラムでもありません。止まったリスナに話し続けるクライアントはトランスポートエラーを受け、再計算しなければなりません。古いヒットは残りません。

インストール、起動、デモ、設定、クォータ、運用メモは 利用マニュアル です。設計目標の図は アーキテクチャ に残します。層の名前は 階層 に残します。
