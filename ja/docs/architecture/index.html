ドキュメント

アーキテクチャ

GPUCache は G3.5 の共有 KV ホット層です。現在の実装はホストメモリと TCP を使います。RustFS はホットリクエスト経路から独立した G4 オブジェクト層です。

開発中

BlueField-3、GDS、実際の RDMA は開発目標であり、NOT_RUN_HARDWARE です。現在の経路はホストコピーを伴い、ゼロコピーや CPU の迂回を主張しません。

現在動く経路

Rust サービスは TCP 経由で Lookup、Reserve/Put、Commit、Get、Release/Cancel、Invalidate を提供します。MemoryStore と FileStore は CPU バックエンドで、FileStore は通常のファイルを使います。各データ操作で認可を確認しますが、mTLS は実装していません。

再利用の前に識別情報を確認

コミット済みで、テナント、信頼ドメイン、モデル、完全なレイアウト識別情報が適合するブロックだけがヒットになります。プレフィックスヒットは保存済みブロック全体を返し、ブロック内部を暗黙に切り出しません。ミス、タイムアウト、チェックサム不一致では再計算します。

単一ノードと複数シャード

単一プロセスを一つのシャードとして使い、同じクライアント操作で拡張できます。ディレクトリは有界メタデータを持ち、クライアントは経路、接続、再試行記録に上限を設けます。メンバー変更時には処理中の操作をフェンスします。経路の epoch スナップショットは運用者が管理し、自動検出や合意形成は実装していません。

独立したコールド層

G4 は v3 マニフェスト、内容ダイジェストによるキー、完全な識別情報の検証を使います。旧マニフェストはミスとなり、遅延や停止時は Missing を返します。失敗した書き込みも有界クレジットを保持し、PUT の成否が不明でも DELETE しません。mock テストは利用でき、実際の RustFS は NOT_RUN_HARDWARE です。

DPU の開発目標

HostSimulation は型付きメッセージ、キャンセル、障害、明示的なドレインを扱います。rdma-nixl と dpu-bf3 は機器 SDK をリンクせず、デバイスを開く操作は拒否します。aarch64 CPU ビルドは BlueField オフロードではありません。実エンジン統合は未検証で、engine-spike は偽のブロックだけを使います。

障害時は再計算

G3.5 は消失訂正符号や永続性のためのレプリカを追加しません。転送完了が不明なら隔離を維持し、明示的なドレインまたは新しいフェンスで再利用を許可します。コールドデータの永続性は RustFS が担います。これはキャッシュ契約であり、災害復旧や大規模運用の検証ではありません。
