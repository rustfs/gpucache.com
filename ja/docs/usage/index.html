使い方

利用マニュアル

次の手順は、きれいなチェックアウトから CPU と TCP の契約を実行します。パッケージのインストール、ディスクのフォーマット、DPU のオープンはしません。BlueField-3、GDS、DPU のハードウェア経路、実 RDMA / NIXL の性能は開発中のままです。

開発中

本番配置はなく、crates.io への公開もありません。Soft-RoCE は機能スモークだけで、性能値ではありません。G3.5 のミスまたはノード喪失はクリーンミスです。再計算し、書き戻します。イレイジャーコーディングはなく、ホット層の耐久レプリカもありません。RustFS は G4 の冷層です。

導入起動デモ設定クォータミス運用メモ

導入

rust-toolchain.toml が Rust stable を選びます。宣言された MSRV は 1.85 です。インストールできるパッケージはありません。リポジトリをクローンし、CPU 契約のテストを実行します。

git clone https://github.com/rustfs/GPUCache.git
cd GPUCache
cargo test --workspace --all-targets

cargo test --workspace --all-targets は V1 A、V1 B、V1 C のワンコマンド CPU 再現であり、ツリーにある V2 と V3 の CPU テストも覆います。バイトは合成です。vLLM の KV テンソルではなく、このコマンドは帯域の結果でもありません。CI は cargo fmt --all -- --check と cargo clippy --workspace --all-targets -- -D warnings も実行します。

起動

明示しない限り、TCP サービスはループバックを聴きます。既定のバインドは 127.0.0.1:9735 です。ループバック以外には --allow-remote が要ります。このフラグは認証を切りません。プロセスは引き続きテナント資格情報のフィンガープリントを要求します。32 バイト、16 進、全ゼロ不可です。生の秘密ではなくハッシュを渡します。認証のないデータ経路はありません。

cargo run -p gpucache-transport --bin gpucache-tcp -- serve --data-dir /tmp/gpucache-dev --tenant tenant-a --trust td-local --fingerprint <64 hex chars of a credential hash>

--data-dir は通常ファイルのディレクトリです（MANIFEST、LRU、blocks/*.gblk）。デバイスノードを指さないでください。プロセスは NVMe をフォーマットせず、NIC を変えず、DPU にも触れません。ディスク上の設定ファイルはありません。フラグがスキーマです。この例は開発用ループバックだけです。

デモ

各バナーは正しさの確認です。性能値ではありません。BlueField-3、GDS、ライブ RDMA は NOT_RUN_HARDWARE のままです。

コマンド成功バナー内容
cargo run -p gpucache-transport --bin share-demostatus=REUSE_OK と partial_prefix=WHOLE_BLOCK_PREFIX2 つのローカルホストクライアントが 1 つのファイルバックエンドを共有します。長い鎖は短いブロック全体を再利用します。より短い valid_length は切り出されません。intra_block_slice=DEGRADED_MISS。
cargo run -p gpucache-transport --bin fault-demostatus=FALLBACK_OK、criteria=EXACT_TOKEN_IDS、tolerance=NONEヒット、ミス、壊れたファイル、期限、キャンセル、クォータ拒否はフェイルクローズです。呼び出し側が再計算します。誤ったテナントやモデルはヒットではありません。vLLM の実行ではありません。
cargo run -p gpucache-transport --bin shard-demostatus=SHARD_OK、registration=SIMULATED、rdma=NOT_RUN_HARDWARE1 シャード、エポックのフェンス、リース期限をまたぐ隔離、TCP のホストコピー。NIC 登録ではありません。
cargo run -p gpucache-cold --bin cold-demostatus=COLD_CONTRACT_OK と gds=NOT_RUN_HARDWAREG4 のモックパック、シンク、予算で止めるリフィル。エンドポイントが無いとき rustfs_live=NOT_RUN_HARDWARE です。
cargo run -p gpucache-dpu --bin dpu-demostatus=DPU_CONTRACT_OK、offload_active=false、hardware=NOT_RUN_HARDWARE、doca=NOT_LINKEDプロセス内の DPU 契約です。デバイスは開きません。Arm プロセスの起動はオフロードではありません。
cargo run -p gpucache-bench --bin paired-baselineNOT_RUN_HARDWARE、時間は出さない対の GPU 基準線は実行しません。サンプル数、TTFT、tokens/s は出しません。
cargo run -p gpucache-bench --bin v3-pairedTCO_UNKNOWN と go_gate=NOT_EVALUATEDNIC RDMA と DPU の比較に名前を付けるだけで、測定しません。TCP はその基準線ではありません。
cargo test -p gpucache-dpu --all-targets --features dpu-bf3テストは通り、オープンは拒否任意フィーチャースロットです。DOCA、SPDK、NVMe はリンクしません。
cargo test -p gpucache-transport --all-targets --features rdma-nixlNixlTransport::open が拒否libnixl はリンクしません。Soft-RoCE は機能スモークだけで、性能値ではありません。

kv-block-xfer は標準入力の GEXP フレームを 1 つ読み、新しい MemoryStore へインポートします。lookup と get が成功したときだけ status=IMPORTED を出します。チェックサム失敗は終了コード 2 です。エンジンには話しません。

cargo run -p gpucache-storage --bin kv-block-xfer -- import <64 hex chars of a credential hash>

設定

設定ファイルはありません。バイナリのフラグと ResourceLimits::dev_defaults() がスキーマです。

フィールド既定意味
bind127.0.0.1:9735ソケット。ループバック以外は allow_remote が要ります。テストはポート 0 です。
data_dir必須通常ファイルのディレクトリ。デバイスノードではありません。
tenant、trust、fingerprint必須1 つの V1 ポリシー。フィンガープリントは 32 バイトで、全ゼロ不可です。
allow_remotefalse認証は無効になりません。
max_connections16超過した接続は落とします。
max_frame_bytesライブラリは 1 MiB、バイナリは 2 MiB本体の上限。宣言が大きければ読む前に拒否します。
pool_buffers16読みバッファプール。上限でチェックアウトは失敗します。
io_timeout5 s接続ごとの読み書きタイムアウト。

オペレータがテストバケットを認可していない限り、GPUCACHE_RUSTFS_ENDPOINT、GPUCACHE_RUSTFS_BUCKET、GPUCACHE_RUSTFS_PREFIX、GPUCACHE_RUSTFS_ACCESS_KEY、GPUCACHE_RUSTFS_SECRET_KEY は未設定のままにしてください。未設定は NOT_RUN_HARDWARE です。資格情報を作らないでください。このマイルストーンの https:// は、TLS スタックが無いため NOT_RUN_HARDWARE です。

クォータ

ResourceLimits は、オブジェクトサイズ、インフライト要求、登録（コミット済みと隔離済みのバッファを含む）、テナントごとのインフライトバイト、全体の保持バイト、テナントごとの保持バイトを境界にします。冪等表には上限があり、項目は期限切れになります。

MemoryStore は退避せず、受付を拒否します。FileStore は、保持バイトのクォータが失敗しそうなとき、ピンされていない最も古いコミット済みブロックを退避します。テナントクォータのために別テナントを退避せず、ピン済みまたは隔離済みのブロックも退避しません。Invalidate がクライアントの明示経路です。

シャードクレジット、模擬スラブ上限、コールド保持、バックフィルのバイト予算は、再計算できる KV の受付天井です。測ったクラスタ規模ではありません。ホット層を利用者データの唯一のコピーとして寸法取りしないでください。

失敗とミス

GPUCache は G3.5 の共有ホット層です。RustFS は G4 の冷層です。G3.5 のミスまたはノード喪失は、クリーンミス、再計算、書き戻しです。イレイジャーコーディングはなく、ホット層の耐久レプリカもありません。

  • ヒットは、互換なアイデンティティを持ち、チェックサムがまだ一致する COMMITTED ブロックだけです。
  • ABSENT、RESERVED、WRITING、EVICTING、QUARANTINED はペイロードを返しません。
  • ミス、タイムアウト、チェックサム失敗、バージョン不一致、ストア停止、予算超過のリフィル、フェンスされたエポック、壊れたまたは切れたファイル、トランスポートエラーは再計算です。成功したヒットではありません。
  • 誤ったテナント、モデル、トークナイザ、アダプタ、レイアウトはヒットではありません。誤ったヒットは故障です。
  • 同じハッシュ鎖のより短い valid_length は非互換ミスです。サービスはブロック内部を切りません。
  • リース期限は、コピーが止まった証明にはなりません。隔離領域は、ドレイン証明か、より新しいフェンス済みエポックまで残ります。
  • 再起動はコミット済みファイルを読み直し、エポックを上げ、進行中の予約を落とします。
  • DPU 再起動、GPU リセット、NIC の瞬断、ストレージ喪失、NVMe タイムアウト、制御プレーン喪失、RustFS の遅延または停止の劣化判断は、すべてクリーンミスです。この表はハードウェア故障注入ではありません。ペイロードなし、誤ヒットなし、恒久ブロックなしです。

エンジンは同じバッチ API で、再計算したブロックを書き戻せます。ホット層は失ったブロックを自分では修復しません。

運用メモ

dpu-demo は診断のスケッチです。dpu-bf3 を選んだか、DOCA / SPDK / NVMe がリンクされていないか、ホット層のイレイジャーコーディングがオフか、計画中の各対象が NOT_RUN_HARDWARE かを出します。ペイロード、フィンガープリント、プロンプトは出しません。デバイスを開いていないので、デバイスの健全性カウンタはありません。

ControlPlane::begin_upgrade は新しいフィルを止めます。進行中のフィルは完了できます。finish 前の rollback はフェンスせずにサービスへ戻します。finish_upgrade はソフトウェア世代を上げてフェンスするので、古いエポックはミスになり、エンジンが再計算します。finish 後の rollback は再びフェンスします。世代カウンタは減りません。このロールバックに BlueField ファームウェア、BFB、DOCA パッケージは含まれません。エラー応答のクォータ種別バイト 8（RateLimit）を除き、TCP のワイヤ形式は変わりません。

リバランスはソースをフェンスし、空の宛先ディレクトリを返します。障害ドメインの隔離はそのドメインのメンバーを外し、最後のメンバーの削除は拒否します。いずれもペイロードバイトはコピーしません。

このツリーが操作しないもの：NVMe フォーマット、DPU モード変更、ファームウェア、IOMMU または BIOS の変更、本番ネットワークの変更。G4 のライブ呼び出しは環境変数のゲートのままです。あとから誰かが Soft-RoCE をスモークしても、それは機能スモークだけで、性能値ではありません。

位置づけと層の分担は 紹介マニュアル です。上流の詳細は OPERATIONS.md と README.md です。
