RUSTFS GPUCACHE · G3.5 開発中

G3.5 層の KV Cache を、DPU 上で動かす。

GPUCache は DPU ベースの GDS KVCache です。GPU メモリに入りきらない KV Cache を、DPU が管理する共有 NVMe フラッシュに置き、必要なときに GPU へ戻します。一度計算したコンテキストを、もう一度計算しなくて済むようにします。

Rust で記述 · Apache 2.0 · BlueField-3 対応は開発中

GitHub で進捗を追う アーキテクチャを見る

位置

  1. G1HBM
  2. G2DRAM
  3. G3NVMe

  5. G4RustFS

GPUCache は G3.5 にあります。ノードローカル SSD より共有しやすく、共有ストレージより推論のホットパスに近い層です。G4 は RustFS が担います。

課題

コンテキストが追い出されると、GPU は再計算する。

長いコンテキスト、複数ターンの対話、Agent によって KV Cache は大きくなり、GPU メモリにはすぐに入りきらなくなります。追い出された KV が再び必要になると、プレフィルをやり直すしかありません。GPU は計算済みの仕事にサイクルを使い、最初のトークンも長く待ちます。

今ある各層には限界があります。ホストメモリの容量は有限です。ノードローカル SSD は一台のマシンにしか仕えず、ノード間で共有しにくい。共有ストレージは永続性と容量のためにあり、推論のホットパス上にはありません。

方針

G3 と G4 の間に、共有の KV Cache を一層足す。

GPUCache は KV Cache 専用のホット層です。DPU が共有 NVMe フラッシュを管理し、GPU クラスタ全体で使います。

  1. 01

    DPU 上で動かす 開発中

    KV エンジンは DPU の Arm コアで動き、フラッシュを直接管理します。ストレージ側に x86 のストレージホストは要りません。BlueField-3 対応は開発中です。

  2. 02

    GDS データパス 開発中

    目標の経路は、GPU メモリから DPU を経て NVMe フラッシュへ直達する形です。KV データはホスト CPU が中継しません。最初の段階では、ホストメモリを経由する経路を通します。

  3. 03

    ホット層だけ。失われれば miss

    GPUCache は永続性を持ちません。ノード障害やデータの喪失は、きれいな miss です。推論フレームワークが再計算して書き戻せば、次はヒットできます。長く残すデータは G4 の RustFS に預けます。

向かない用途

  • 永続して残すデータ。G3.5 はキャッシュです。永続データは G4 の RustFS に置きます。
  • 学習のチェックポイント保管。それは G4 の仕事です。
  • 今すぐ本番へ載せること。V1 はまだ開発中です。

アーキテクチャ

GPU、DPU、フラッシュ。それぞれの仕事がある。

GPUCache は KV データのホットパスを、NIC、DPU、SSD の間に置きます。下図は設計目標です。コンポーネントはすべて開発中です。

  1. GPU メモリ / ホストメモリ
  2. RDMA / RoCEv2
  3. DPURust KV エンジン
  4. SPDK
  5. NVMe フラッシュ

開発中

  1. 01

    Rust KV エンジン 開発中

    KV Cache 向けのストレージエンジン。Rust で書き、DPU の Arm コアで動かします。

  2. 02

    RDMA / RoCEv2 転送 開発中

    計算ノードと G3.5 の間は RDMA で通信します。

  3. 03

    SPDK によるフラッシュ管理 開発中

    DPU 上の SPDK で NVMe SSD に直接アクセスします。

  4. 04

    NVIDIA DOCA と Arm クロスコンパイル 開発中

    BlueField-3 上でビルドし、実行します。

  5. 05

    推論フレームワークとの接続 開発中

    vLLM や TensorRT-LLM などの KV Cache インターフェースへ接続する予定です。PagedAttention のブロック粒度で管理します。

データパスは三段階で進めます。ホストメモリ経由、次に一時置き、その次に GDS 直通です。検証できた組み合わせだけを「GDS 直通に対応」と書きます。 アーキテクチャの説明

RUSTFS との関係

G3.5 は熱いものを置く。G4 は残すものを置く。

RustFS を見る

GPUCache は RustFS チームが作っています。ストレージ階層での分担は明確です。GPUCache は G3.5 のホット層で、GPU の近くにあり、再利用するためのものです。RustFS は G4 の容量層で、Rust で書いた S3 互換の分散オブジェクトストレージです。モデル、データセット、セッション履歴、推論の成果物を永続して保管します。

ホット層を失っても再計算できます。容量層のデータは失えません。二つの仕事を分けると、それぞれが単純になります。
