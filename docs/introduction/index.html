Introduction

Introduction

GPUCache is the shared KV hot tier at G3.5. RustFS is the colder G4 capacity tier. The path you can run from this tree is a CPU and TCP contract. BlueField-3, GDS, the DPU hardware path, and real RDMA or NIXL performance are in development.

ImplementedIn development

V1 A/B/C and the V2 CPU slice are in the main tree. V3 is a DPU feature gate and production-hardening stubs. Hardware paths print NOT_RUN_HARDWARE. Soft-RoCE is a functional smoke only, not a performance number.

Product positioning

GPUCache is an open shared KV-cache tier for disaggregated inference. In NVIDIA CMX terminology that tier is G3.5: a shared cache in front of GPU HBM, reused across requests that have the same tenant, model, and layout. RustFS is the G4 capacity backend. G4 is not on the prefill-to-decode hot path.

A KV block is recomputable accelerator state. It is not the user's only copy of a prompt, and it is not model-agnostic long-term memory. The inference engine still owns tokenization, attention, and scheduling. This repository does not replace them.

A miss, timeout, checksum failure, version mismatch, or store outage falls back to the engine. The engine recomputes, then may write back. A wrong hit is a failure. There is no erasure coding and no hot-tier durability replica. There is no installable package, no production deploy, and no measured cluster size. Do not describe this tree as PB-scale or production-ready.

The license is Apache 2.0. Public wording follows the main-branch README and the docs beside it.

What runs, and what is in development

The default build is CPU and TCP. It does not link DOCA, CUDA, RDMA, NIXL, or SPDK. An aarch64 build is a CPU build. It is not a BlueField functional test. Feature rdma-nixl does not link libnixl. Feature dpu-bf3 does not link a device. NixlTransport::open, open_doca, open_nvme_device, and open_spdk refuse.

Architecture

The drawing on the home page is the design target for a DPU path. It is not a path this tree has run. The tree that runs looks like this:

engine (not in this tree; NOT_RUN_HARDWARE)
        |  CacheIdentity + batch API
        v
gpucache-transport    TCP, loopback by default
        v
FileStore             ordinary files in a directory you pass
        v
MemoryStore           in-process contract
gpucache-cold         optional G4 mock. Not on the TCP hot path.
gpucache-dpu          simulated queue. Not on the TCP hot path.
  • gpucache-core-types holds versioned CacheIdentity, length-delimited logical and physical keys, the block lifecycle, checksums, quotas, and errors.
  • gpucache-protocol holds batch messages, deadlines, tenant auth context, and wire-version negotiation.
  • gpucache-storage holds MemoryStore, FileStore, and kv-block-xfer. FileStore does not format a disk and does not open a device node.
  • gpucache-transport is the TCP correctness path, plus a simulated registered-buffer pool and a shard-local directory.
  • gpucache-cold packs a manifest and can Put, Head, RangeGet, and Delete through a trait. Transport does not depend on it.
  • gpucache-dpu is the BlueField feature slot. The hot path does not call it.
  • gpucache-bench names paired baselines and prints NOT_RUN_HARDWARE. It must not invent timings.

Only a COMMITTED block whose identity is compatible, and whose stored checksum still matches the bytes, is a hit. ABSENT, RESERVED, WRITING, EVICTING, and QUARANTINED are not readable.

ABSENT -> RESERVED -> WRITING -> COMMITTED -> EVICTING -> ABSENT
                 \-> QUARANTINED -> ABSENT

A failed or timed-out registered region goes to QUARANTINED. Lease expiry does not free it. Reclaim needs an authorized drain attestation, or a newer epoch that fences the region. A longer hash chain can return PrefixHit for a whole shorter committed block when layout and the other byte-affecting fields match. The service does not slice inside a block. A shorter valid_length on the same chain is an incompatible miss.

Raw prompts, token ids, and media bytes are not identity fields. Callers hash those outside the store. Same tokens do not imply the same bytes: the logical prefix key and the physical byte key are different encodings. Reuse stays inside one tenant, one model, and one layout. A reshard, quant, or layout mismatch is a miss. There is no cross-tenant dedup.

G3.5 and G4

GPUCache at G3.5 is the shared hot tier. RustFS at G4 is the cold capacity tier. The hot tier does not repair lost blocks. There is no erasure coding and no hot-tier durability replica. Loss, corruption, a short write, a full disk, eviction, and a failed check are a clean miss. The engine recomputes, then may write back.

If the on-disk write fails after the in-memory commit, that commit is abandoned and the request id is forgotten, so a replay cannot report success for bytes that were not stored. An extra copy of a hot shared prefix, if one is ever added, would be a latency hint. It is not in this tree, and it would not be a durability promise.

Cold durability is RustFS's job. The TCP service does not call the cold crate. Refill that is over budget, or a slow or down RustFS, returns no payload. That outcome is a recompute, not a hit. https:// to a live bucket is NOT_RUN_HARDWARE here because no TLS stack is linked. Leave GPUCACHE_RUSTFS_* unset unless an operator has authorized a test bucket.

One protocol, from a single node toward a distributed tier

The batch API is the same on every runnable path: Lookup, Reserve/Put, Commit, Get, Release/Cancel, and Invalidate. Every item carries request_id, epoch, and deadline, and, where it applies, generation, length, and checksum.

MemoryStore is the in-process, single-threaded contract. The TCP service serves that same API. Shard 0 is the single-node case and uses the same ShardDirectory methods as any other shard. One process is one shard. There is no per-token central directory and no per-block quorum. A membership change bumps the epoch, drops in-flight fills, and releases credits. Joiners of a single-flight fill do not reserve a second credit and do not receive payload bytes from the directory.

That is the whole step from one node toward a distributed tier in this tree: same protocol, same directory methods, still one shard per process. Cross-shard distribution is not a second wire protocol, and it is not a running quorum. A client that keeps talking to a stopped listener gets a transport error and must recompute. It does not keep a stale hit.
