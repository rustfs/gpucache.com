Roadmap

Status separates available source and reproducible CPU contracts from hardware qualification. This roadmap promises neither a release date nor measured fleet capacity.

StatusCapabilityBoundary
CPU/TCP availableIdentity, lifecycle, MemoryStore/FileStore, TCP ACL and reader admissionSynthetic tests; trusted network boundary, no mTLS.
CPU/TCP availableBounded shard clients, membership updates and epoch fencingOperator-managed routing; no distributed consensus or fleet-size certification.
Mock contract availableG4 manifest v3, bounded sink, refill and retentionLive RustFS: NOT_RUN_HARDWARE. Orphan collection is not automatic.
CPU simulation availableDPU messages, fault injection and functional TCP comparisonNo device offload, zero-copy, throughput or TCO evidence.
Fake-block spike availableEngineBlockContract and engine-spikeReal vLLM export/import: NOT_RUN_HARDWARE; GPU/model run: NOT_RUN_BUDGET.
In developmentReal RDMA, GDS, BlueField-3 / DOCA and SPDKNOT_RUN_HARDWARE. Optional features remain unlinked and fail closed.

Next evidence gates

Qualify a real engine with authorized GPU/model resources, then measure hardware paths against the appropriate paired baseline. Keep TCO_UNKNOWN and NOT_EVALUATED until that evidence exists. Source availability does not establish an installable release or production readiness.

Preserved boundaries

RustFS remains off the hot path. G3.5 loss leads to recompute; no hot erasure coding or durability replicas are planned. Scaling requires bounded shards, fencing and clean misses, not a verified 10,000-GPU claim.
